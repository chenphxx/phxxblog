# 技术架构与实现说明

`phxxblog`是一个前后端分离的个人博客系统, 前台与管理后台共用同一套REST API 

## 技术栈

| 层     | 技术                                                                                                                          |
| ------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 前端   | Vue 3, TypeScript, Vite, Vue Router(hash 模式), Pinia, Axios, Element Plus, Vditor                                            |
| 后端   | Python 3.10+, FastAPI, SQLAlchemy 2.x(声明式 ORM), Pydantic v2 / pydantic-settings, PyMySQL, PyJWT, bcrypt, feedgen, Markdown |
| 数据库 | MySQL(utf8mb4 / utf8mb4_unicode_ci)                                                                                           |
| 其他   | ip2region 离线 IP 库(vendored, 可选)                                                                                          |

**没有引入数据库迁移工具**: 新表由启动时的建表动作创建, 已有表加列需要手工写迁移 SQL 并登记 应用启动会校验模型与库结构是否一致, 缺列则拒绝启动 

## 系统架构

```text
浏览器 (Vue3 SPA: 博客前台 + 管理后台, Pinia 状态 / Axios 请求 / Element Plus 组件)
   │
   │  Axios → /api/v1/**          上传与静态资源 → /assets/**
   ▼
Vite 开发代理(frontend/vite.config.ts, 仅开发环境)
   │  /api  /assets  /docs  /redoc  /openapi.json  →  http://localhost:8000
   ▼
FastAPI(backend/app/main.py)
   ├─ modules   模块体系: 每个能力一个包(spec 元数据 + router 接口) + 注册表/装配
   ├─ core      配置, 安全(JWT/bcrypt), 权限码, 中间件, 统一响应
   ├─ services  业务服务(渲染 / 上传 / 统计 / 导入导出 / 文章查询与写入等)
   ├─ models    SQLAlchemy 模型        ├─ schemas  Pydantic 请求与响应模型
   ▼
MySQL(SQLAlchemy + PyMySQL); 上传文件落盘在 assets/, 由 /assets 静态目录对外提供
```

## 模块体系

一项能力(评论, 媒体库, 日记, RSS, 一言 …)就是一个模块: 一个自包含的包, 里面有元数据与接口实现, 由注册表统一登记 

```text
app/modules/
  base.py       ModuleSpec / ModuleSetting 定义(含 module.<id>.<key> 键规则与配置类型) 
  registry.py   注册表: 登记与一致性校验, 全局单例
  state.py      开关与配置的读写, 以及"真正可用"的判定
  deps.py       require_module 依赖: 模块未启用时该模块的接口返回 404
  router.py     装配: 把注册表里的模块装成 API 路由与根路径路由
  <模块 id>/    __init__.py(导入即注册) + spec.py(元数据) + router.py(接口)
```

完整的接口清单见 `docs/接口文档.md` 

## 前端模块注册表

前端与后端共用同一套模块 id 一个模块在前端声明导航入口(前台与后台)与页面路由, 由统一函数打上模块标记 路由表只保留布局自身的东西(首页, 登录页, 个人资料与后台重定向), 其余页面全部来自模块注册表 

- **路由守卫**: 目标路由带模块标记时先确保模块状态已加载, 模块不可用则送回首页 懒加载的页面组件在守卫之后才解析, 因此禁用模块不会下载它的代码 
- **导航与区块**: 侧栏入口由注册表生成并按模块状态过滤; 首页与详情页的模块化区块同样按开关决定是否渲染与请求 
- **纯前台模块**: 没有导航也没有页面路由的模块(终端卡片, 主页简介, 个人资料卡, 页脚, 网站链接, SEO, 看板娘, 代码块字体, 正文字号, 回到顶部)同样登记 id 与说明, 后台"模块管理"因此能一处看到"关掉会发生什么"; 它们的页面来自布局与首页, 自身不注册路由 
- 新增一个功能模块只需两处: 后端加模块包并登记, 前端在注册表加一条记录(需要页面就写路由), 之后由脚本核对两侧 id 一致 路由汇总, 布局组件与权限表都不应因为加功能而被改动

## 数据模型概览

| 表                          | 说明                                                                                    |
| --------------------------- | --------------------------------------------------------------------------------------- |
| users / roles / permissions | 用户, 角色, 权限及两张多对多关联表; 刷新令牌另表存散列                                  |
| posts / categories / tags   | 文章(状态, 摘要, 封面, 阅读量, 点赞数, IP 与归属地)与分类, 标签(含颜色), 两组多对多关联 |
| comments / post_likes       | 评论(自关联多级回复)与点赞去重记录                                                      |
| media                       | 上传文件元数据与实际路径                                                                |
| diaries                     | 日记(仅管理员, 支持附件)                                                                |
| visit_logs / daily_stats    | 访问明细与按日聚合统计                                                                  |
| operation_logs              | 操作日志                                                                                |
| settings                    | 键值对配置: 站点身份键, 平台约束键, 模块配置(module.<id>.<key>)与一言缓存共用此表       |

字段级说明见 [数据库设计.md](./数据库设计.md)
